# 产出格式

## 目录
1. 作业讲解（每题五段）
2. 讲义讲解 / 对照导航
3. 考前复习：零基础补课册 + 题型解法卡
4. 编程上机 / 代码作业：带做卡（每题六步）
5. 以做题为主的课（如大学物理）

全部服从 `writing.md`：全中文、先直觉、每步写理由。

---

## 1. 作业讲解（每题、每小问）

1. **题目在问什么**：人话复述，考什么、要证/算/构造什么；小问之间的关系。依赖图的题先嵌原题图；题单和老师原文有出入的，在这里注明。
2. **要用的知识**：定义/定理带老师讲义编号和页码，写成「条件 ⇒ 结论」+ 一句直观；点出核心工具；前置知识没学过的就地补。
3. **解题思路**：先给骨架，讲为什么用这个方法；关键技巧提前点出。
4. **完整解答**：中文，无跳步，每步有依据。计算题终答 `\boxed{}`，证明题以 $\blacksquare$ 结尾。
5. **总结**：一行结论；证明题点出最关键的一步；同类题怎么下手；最容易错在哪。

题图看不清标「需要确认题图」并给出能确定的部分。

## 2. 讲义讲解 / 对照导航

**讲义讲解**（老师讲义是主线时）按原文顺序：
- 开头一小节「这一节在讲什么」：在整门课的位置、要解决的问题、读的时候盯住什么。
- 每节开头写一次出处（老师讲义第几页到第几页），不必每段挂页码。
- 每个定义：直觉 → 定义（中文）→ 逐个记号解释 → 例子（算出来）→ 反例 → 和前后内容的关系。
- 每个定理：它在说什么（人话）→ 条件 ⇒ 结论 → 为什么需要每个条件（去掉的反例）→ 证明思路 → 完整证明 → 怎么用。
- 节末：本节要点 3–5 条、易错点、2–3 道小练习（答案放全文最后）。

**对照导航**（用户以视频或中文教材为主线时）只做主线做不到的事，短：
- 老师编号 ↔ 视频集数/时间段 ↔ 教材章节对照（一张表）
- 老师独有、视频和教材不讲的内容：按讲义讲解的写法讲
- 老师讲义的笔误：原文写的、应为什么、理由（每条都渲染原页核过）
- 哪些可以跳、考前看哪几集

## 3. 考前复习（两份配套）

**① 零基础补课册**：把后面题型要用的前置知识从最底层补起，编号 K1、K2…按依赖顺序（先学的在前）。每条：
一句人话 → 带数字的小例子（算一遍）→ 一个「不是它」的反例 → 能画就配小图 → 结尾写「后面哪些题型会用到它（T 编号）」。

**② 题型解法卡**：
- 第 1 页：总表（题型｜认出它的信号｜核心方法｜作业原型题号｜往年题/练习题对应）+「这几天怎么用」（先补 K → 读题型 → 合上书重做原型题 → 做同类题）。
- 每个题型固定小块：
  - ⓪ 先补哪几条：0a 的 K 编号
  - ① 认出它：题目里出现什么字眼/对象就是这类
  - ② 解题套路：每步「做什么 + 为什么 + 靠哪条定理」
  - ③ 要用的知识：条件 ⇒ 结论 + 直观 + 条件缺了会怎样；最容易漏的条件单独点出
  - ④ 原型题：完整中文解答，按 ② 的步骤一步步来，计算写出中间式子
  - ⑤ 考场写法：卷子上怎么规范地写出关键句（按考试语言）+ 易错
- 最后一节「判断题怎么答」：对/错 + 一句依据（定理名或反例名）。

自查要点：全部作业题都在某个 ④ 里（逐题打勾）；②里 ⓪ 指的 K 在①里真实存在，①里写的 T 编号和②一致（可以写个小脚本交叉检查）。

## 4. 编程上机 / 代码作业：带做卡

一张卡讲 1–2 题，**宁可多切几张卡，也不把一题压成一两页**。每题六步：

**① 题目完整翻译**：题单该题原文（注明第几页）、notebook 里该题说明、代码里每条 `# TODO` 和注释、检查要求，逐段译成中文并标出处；附术语表（原词｜中文｜一句话），同词不同义要提醒。告诉读者题单 PDF 在哪。

**② 它在问什么**：一两句人话：要写出什么、输入输出是什么、和前面哪题、哪块数学有关。

**③ 数学模型（最重要）**
1. 先写**菜谱**：中文写算法通用步骤（「对每一轮 k：对下面每一行 i：①…②…」）。
2. 用题单里的小例子**一次只做一个动作**地手算，每个动作写「数怎么来 → 怎么算 → 结果」。
3. 每个动作后放「✋ 先自己算」小框，紧接着「核对」。
4. 每一步画出数组/矩阵的当前状态。
5. 手算结果和检查格要的结果对上。
6. 手算步骤和菜谱逐条对照。

**④ 名字来源表**：这格里每个名字｜从哪来（本格造的 / 前面第几格造的 / 函数内部临时的）｜是什么｜在哪看得到；外加「到目前为止每一格造了什么」清单。固定比喻：**变量＝贴了标签的盒子；函数＝一台机器，入口的名字和外面放进去的东西名字可以不一样**（榨汁机入口叫「水果槽」，放进去的是「苹果」）。

**⑤ 转化成代码**
1. 整格代码分块标注（准备 / 循环 / 要填的 / 收尾），老师写好的每一行逐行讲：代码｜意思｜对应手算哪一步。
2. 菜谱 ↔ 代码零件对照表。
3. **你先写**：列出要填的空和零件提示。
4. **参考答案**（放在「你先写」之后）+ 逐块解释。
5. 代入数字把整个循环跑一遍，每次循环写出变量的值和数组状态。
6. 操作步骤（改哪里、运行哪几格）+ **真实运行得到的**期望输出。

**⑥ 结论 + 找错**：这题说明了什么、和前后题的联系；常见错误 1–3 个：错误写法 → **真实跑出来的**错误输出 → 怎么从报错和反常数字倒推错在哪；教她读报错里的箭头指向哪行、在比什么。

第一次出现时要单独讲：`=` 两边同名不是方程（用旧值算新值再存回去）；`*` 和 `@`；`range(a, b)` 不含 b、倒着数；切片用「刀口图」（元素之间的刀口从 0 编号）；Python 从 0 数、题单从 1 数，两套编号并排写。

输出必须真实运行得到；用和她**同版本**的 Python 与库跑（版本不同输出会变）；**不要动她自己的环境**，另建一个虚拟环境跑。

## 5. 以做题为主的课（如大学物理）

- 理论讲够用：定义、物理图像、适用条件、和哪些题型挂钩。
- 老师课件的每道例题完整解，解完抽套路；每节再补 2–4 道教材同类题，标「补充题」；标出每题通常以填空还是计算出现。
- 节末「题型速查表」：题型｜认出它｜首选方法｜常见坑。

三条硬要求：
1. **每个方程讲清凭什么能列出来**：受力分析（几个力、方向、为什么）、坐标原点为什么这么选、用哪条定律以及为什么这里能用、近似条件（去掉会怎样）、每个负号的意思。
2. **微分方程真的解一遍**：老师写「其通解为」的地方，从特征方程一路解到通解、化成标准形式、代初始条件定常数。
3. **图要截下来嵌进去**：受力图、矢量图、曲线、电路图。

课件如果是 PPT 转的 PDF，公式在文字层里是乱码，一律渲染成图看（见 `sources.md`）。
