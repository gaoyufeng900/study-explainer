# 交付前自查

没有人复审，所以要假装这份是别人写的、你在挑它的错。

## 1. 什么问题必须修

- 数学/计算错（独立重推关键步骤；排版漂亮不等于对）
- 引用定理时条件不满足
- 漏讲老师原文的条目、漏了作业题或小问
- 公式没渲染、代码块被压扁、该有的图没嵌
- 讲了老师还没讲到的内容却没标「补充」
- 违背学习者档案或 `writing.md`：出现英文段落、「显然」、AI 腔、表格堆砌

**不必反复返工**：孤零零的标题、行距、页数、表格宽度——顺手改，改不动记进日志。

## 2. 跑扫描（每次必跑）

```bash
python3 <本skill目录>/scripts/check_all.py 成品.pdf [更多.pdf] --md 源码.md [更多.md]
```

| 检查 | 抓什么 |
|---|---|
| 正文 TeX 生码 | `x_k`、`_{`、`\lambda` 印在正文里——行内公式的反斜杠丢了 |
| 未渲染数学 | 正文里字面的 `^`，如 `(L^p)` |
| 孤悬标题 | 页底只剩一个标题，正文跑到下一页 |
| 代码块 | 代码被排成普通段落（`python` 字样漏出、行数对不上） |

这些问题排版引擎认为完全合法，日志里一个警告都没有，肉眼翻几十页也必漏——所以靠脚本。
- 每条命中都渲染那一页确认（代码里的 `x_new` 这种是合法的，脚本已按等宽字体排除）。
- 换了标题颜色就加 `--heading-color 十六进制色`。
- **修完整份重扫**：修的时候新写的句子常常又把公式写坏。

## 3. 渲染看图

```python
import fitz
doc = fitz.open("成品.pdf")
for i, page in enumerate(doc):
    page.get_pixmap(dpi=100).save(f"_check/p{i+1:02d}.png")
```
逐页看：裁切、重叠、乱码、图没出来、表格溢出。页多就几页拼成一张看。

## 4. 内容核对清单（写进核对记录）

1. **覆盖**：列出原文条目/作业题号清单，逐个找到在正文哪里；打勾前回正文确认真的写了，不是只写了一句结论。
2. **答案**：和第二步验算基线一致；计算题代特殊值/对称性/已知特例再查一次；反例两个方向都验。
3. **指路页码**（「完整解答见第 y 页」）用脚本在 PDF 里查实，不要估。
4. 说「老师讲义有错」的每一处，都渲染原页确认过（文字层会丢上横线、上标，误判过）。
5. 读者三问：零基础的人只读这份，能说出这节在讲什么吗？每个符号能读出来、说出意思吗？有没有结论直接抛出、过程略掉的句子？

## 5. 交付说明（写进日志，也简短告诉用户）

成品路径与页数 · 覆盖了哪些条目/题 · 扫描结果 · 发现的原文问题（讲义疑似笔误、题单与原文不一致）· 自认没做到或拿不准的地方。
