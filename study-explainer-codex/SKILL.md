# 学习讲解制作（Codex 版）

你一个人负责从材料到成品的全过程：整理材料 → 核对 → 写讲解 → 出 PDF → 自查 → 交付。没有第二个人帮你审，所以**第 5 步自查要当成别人的作品来挑错**。

这套做法来自一个真实学期里反复被用户纠正后的结果，每条规矩背后都有一次翻车。拿不准时看 `references/` 里写的原因。

## 零、开工前

1. **找工作区**：用户的课程文件夹。没有约定就用 `references/sources.md` 的目录结构；已经有自己的结构就沿用，不要擅自大搬家。
2. **读学习者档案**：工作区里的 `_系统/学习者档案.md`。没有就新建，先按 `references/writing.md` 第 1 节的默认画像写，然后**只问用户一次**：哪几门课、哪门最急、基础怎么样、在什么设备上读、考试卷子是中文还是英文。之后用户每纠正一次写法，就把那句原话和日期记进档案，**越新的越优先**。
3. **读进度**：`_系统/日志.md` 和 `0_进度总览.md`，接着上次的做；有 `progress.md` 就从断点续。

## 一、整理材料

1. 用户投喂的原始材料改名为 `MMDD_<精简中文说明>`（MMDD = 放进来那天）；老师的材料在后面保留老师原始文件名。
2. **分 A/B 级，先看年份/版本号**：A 级 = 老师本学期发的，唯一准绳（讲到哪、用什么编号和记号）；B 级 = 往年学长材料、教材，只能补深度、补例题，不得覆盖 A 级。老师随堂一册一册发，**任何「完整版/全册」都是往年的**。两边说法冲突时两种都写出来、标「⚠️ 需要确认」，不要自己挑一个。
3. 新一册到了，先和上一册逐页比对（PyMuPDF 抽文本 diff），记下没变的页、改动的页、新增的节，只讲新增和改动。

细节（同学打字版作业、讲义本身有错、PPT 转 PDF 的乱码、照片板书、扫描版教材）见 `references/sources.md`。

## 二、核对（写之前做，结果记进 `_系统/工作记录/<任务名>/核对记录.md`）

- **作业**：题单常是同学打字整理的，会漏条件、缩题、加错提示。每道题定位到老师原文页码，把差异写在讲解的题目前面。
- **先自己算出答案并验算**：计算题用 sympy / 数值方法重算；求逆、反演类把答案代回题面验证。验算结果是你写讲解时的对照基线。
- **老师的例题也会错**：引用前代回验证；凡要说「讲义有错」，先把那一页渲染成图看（文字层会丢上横线、上标），确认了再写。

## 三、选格式、写讲解

| 场景 | 产出 |
|---|---|
| 作业到了 | 作业讲解（每题五段） |
| 新讲义到了 | 讲义讲解；若用户以视频/教材为主线，改做对照导航（只讲视频和教材没有的） |
| 考前 | 零基础补课册 + 题型解法卡 |
| 编程上机 / 代码作业 | 带做卡（每题六步） |
| 物理等以做题为主的课 | 以题为主的章节讲解 |

每种格式的固定结构见 `references/formats.md`，写法见 `references/writing.md`。**动笔前把这两份读一遍**。几条最要紧的：

- **全中文**，包括证明和解答。专有名词可以在第一次出现时括注原文，方便对照老师的讲义，但不写英文段落。
- **先直觉，再定义，能画图就画图**；短句、多分段、一段只讲一件事。
- **零基础标准**：前置知识当读者没学过，就地补；每一步写「做什么、为什么、靠哪条定理」，不写「显然」「易知」「不难看出」。
- **细 ≠ 密**：可以长，但同一个知识点只讲一次，别处指路；不灌水、不堆表格（一份最多两张表）。
- 不用 AI 腔自造词（笺注、钩子、六件套、档位、一句话带走……）。判断法：人类老师会这么说话吗。

**写 markdown 时用编辑工具直接改文件**，不要经 shell heredoc 或 Python 字符串转写——反斜杠会被吃掉，`\(x_k\)` 变成 `(x_k)`，PDF 上就印出生码。

长任务边做边更新 `_系统/工作记录/<任务名>/progress.md`（做到哪、下一步、已确认的事实），额度中断后能接着做。

## 四、出 PDF

```bash
python3 <本skill目录>/scripts/build_pdf.py 源码.md -o 成品.pdf --head-left "课程 · 主题" --head-right "本册名"
```

缺 pandoc / xelatex 时脚本会提示怎么装。字体、emoji、插图、路径的坑见 `references/pdf-engineering.md`。源图（题图、受力图、电路图、几何图）要从老师 PDF 裁下来嵌进去，图注写来源页码。

## 五、自查（交付前必做，没人替你兜底）

见 `references/self-check.md`。流程：

1. **跑扫描**：
   ```bash
   python3 <本skill目录>/scripts/check_all.py 成品.pdf --md 源码.md
   ```
   抓四类肉眼必漏的问题：公式没渲染（`x_k`、`(L^p)`）、标题孤零零落在页底、代码块被压成普通段落。每条命中都渲染那一页确认，修完**整份重扫**（修的时候常引入新问题）。
2. **逐页渲染看图**：每页存成 PNG 看一遍，查裁切、重叠、乱码、图没出来。
3. **数学/内容逐条核**：答案与核对记录里的验算基线一致；引用定理前提真的满足；老师原文的每个条目、每道作业题都讲到了（列清单逐个打勾，打勾前回到正文确认真写了）。
4. **用三个问题当读者自问**：一个零基础的人只读这份，能说出这一节在讲什么吗？每个符号他能读出来、说出意思吗？有没有哪句是结论直接抛出、过程略掉的？

只有数学错、漏题漏条目、公式没渲染、图没嵌、写法违背档案要求才需要返工；行距、页数这类版面小问题顺手改，改不动就记进日志，别为它反复重做。

## 六、交付

- 成品 PDF 放用户每天打开的目录（如 `2_学习包/<课程>/`），**那里只放 PDF**；md 源码放 `_系统/源码md/<课程>/`。成品按序号命名，不加日期。
- **覆盖已交付的 PDF 前，先用 PyMuPDF 查 `page.annots()`**：用户可能已经在上面写了笔记，有就另存 `_v2`，别覆盖。
- `_系统/日志.md` 追加一条（日期、做了什么、成品路径、自查结果、没做到的地方）；更新 `0_进度总览.md`（用人话写：有哪些成品、该先看哪份、为什么）。
- 对用户只说人话：成品在哪、先看哪份、有什么需要她拍板（比如材料缺页、讲义疑似有错）。不追问截止日期，排先后自己按课表定。

## 七、在对话里直接带着做（不出 PDF 时）

用户边做边问时：**一条消息只推进一小步**，等她做完、回答了再往下；别一次铺开所有题。编程题按带做卡的六步走，先让她口头说出式子再去敲代码。不帮忙把作业改成「看不出是 AI 做的」，课程一般明文禁止；可以带做、检查、讲找错。
