# 任务书（派活提示词）

## 写作要点

- **自包含**：执行方只读得到任务书和仓库文件。版本号、路径、你验收时实测到的数值、讲义勘误、上一册到这一册改了什么，全写进去。
- **规范与任务书分开**：长期规矩写进仓库里的规范文件（执行方每次都读），任务书只写本次的事并引用规范的节名。
- **阻断项放末尾成清单**：凡必须出现的内容（「必须写出老师给的三个谱半径」）都进清单，不埋在背景段落里。
- **详细解题类**：附一道完整的黄金范例当质量锚，或明令「每题 ≥N 步编号推导、禁止通用套话、变式必须是新题且附完整解答」。只给一行压缩答案会被做成 53 道空模板。
- **不把 agent 指令写进源料**：`[Claude 已核]`、「Codex 写时改正」这类字会被印进学生 PDF。
- **事实都给可核验的出处**：页码让执行方用脚本查实；作业题号逐个核对；讲义存疑写进单独的核对记录。
- **续跑**：要求边做边更新 `codex工作记录/<任务号>/progress.md`；重派时第一句写「先读 progress.md 与 findings.md，从断点续做」。
- **追加要求写在末尾**，加「🆕 日期 追加（优先于上文冲突处）」横幅，不改前文，方便执行方看出哪里变了。
- **重编已交付成品**：要求落位前查 `annots()`，有批注不覆盖。
- **最终回复要什么**：PDF 路径与页数、覆盖清单、发现的原文问题、自认没做到的地方。

## 派发与档位

```bash
# 在常年在线的机器后台跑；wait 用后台方式跑，完成即收到通知
dispatch new "<工作区>" --net --model gpt-5.6-sol --effort high <<< "$(cat 任务书.txt)"
dispatch wait <编号>
```

| 活 | 档位 |
|---|---|
| 讲义、导航、题型、零基础补课、带做卡（篇幅长要逐步推演） | Sol + high |
| 短上机卡、留白是对的作业讲解 | Terra + high 也可（实测省一半额度，密度 −60%，阻断项必须写全） |
| 任何活 | 不用 Luna（长上下文召回 41% vs 91%） |
| 某一张卡怎么都做不好 | 单独那张升 `max`；不开 `ultra` |

篇幅不随档位走：Sol 也会写得很紧但内容完整，嫌紧就在阻断项里写「每道题写完整自然段，列式理由单独成段」。

## 撞额度时：Sonnet 接替

用户授权：Codex 因额度中断时，不干等。
1. 先停掉原任务的定时续跑，并确认进程真没了（`pgrep -fl` 为空），**同一任务同一时刻只许一方写**。
2. 用 `dispatch new <目录> --claude sonnet --effort high` 在同一台常年在线的机器后台跑，提示词 = 同一份任务书 + 「从 progress.md 断点续做」+ 已验收的改动 + 运行环境 + 禁止改派活单/规范/别的任务文件。
3. 验收标准与 Codex 交付完全相同；日志写「Sonnet（接替 Codex）」。
