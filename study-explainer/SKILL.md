# 学习讲解制作流程

这套流程是在一个真实学期里一边做一边被用户纠正出来的。每条规矩背后都有一次翻车，`references/` 里写了来历，拿不准时去看原因，不要只背条文。

## 一、谁干什么（最重要，复发过四次）

- **Claude 只做四件事**：① 定规范、改规范；② 拆任务、写任务书派活；③ 验收（数学复核、阻断项复核、程序化扫描、渲染抽查）；④ 不合格就退回，或者做最小必要的定点修补。
- **整张卡、整份讲解、整份 PDF 的生成交给 Codex。** 「我手上有第一手事实」「这张很小」「顺手就做了」都不是自己动手的理由——把那些事实写进任务书，让 Codex 照着写。
- **「帮我完成作业」也走这条线**：Claude 自己算的答案只当**验算基线**写进任务书（sympy / 数值积分 / 参考实现），讲解由 Codex 出，Claude 验收。对话里只报进度和需要用户拍板的事。
- **整理输入不算生成**：把板书照片转录成 markdown、把 PPT 转出的 PDF 渲染成图核对，这是让 Codex 能开工的前置活，Claude 可以做。
- **例外只有两种**：用户当次明说「这条你自己做」；或 Codex 撞额度卡住，由**子代理 Sonnet 按同一份任务书从断点接替**（用户已授权，见 `references/task-book.md` 末节）。主会话 Claude 仍然不生成。
- 额度问题、要不要改分工，先问用户，不自己决定。

## 二、一次任务的完整步骤

### 0. 材料入库
1. 用户投喂的原始材料改名为 `MMDD_<精简中文说明>`（MMDD = 用户放进来那天）；老师的材料在后面**保留老师原始文件名**（老师的幻灯/模板会按原名互相引用）。
2. **判 A/B 级先看年份/版本号**，不要看内容全不全：老师随堂一册一册发，**任何「完整版/全册」都是往年学长的**。A 级（老师本学期发的）是唯一准绳，B 级只能补深度、补题，不得覆盖 A 级。冲突时两种说法都列出、标 `⚠️ 需人工确认`，不许自己裁决。
3. 新一册到货先和上一册逐页比对（PyMuPDF 抽文本 diff），写清「哪些页没变、哪页改了什么、新增哪些节」，这段结论直接写进任务书。
4. 有扫描器就重建基线（`watch_materials.py --full`），否则改名会被误报成「删除+新增」。

细则（打字版作业、讲义勘误、PPT 文字层、照片转录）见 `references/sources.md`。

### 1. 排优先级
- 只用两类可核实的依据：**课表 ics 里的下次课**、**用户亲口说的截止日**。别猜「这章下周才讲」——课件到货当天多半就是当天讲的。
- ics 多数课是 `RRULE` 重复事件，按 `DTSTART` 筛会漏，要展开 `FREQ=WEEKLY;INTERVAL=N`。
- **不追问截止日**（用户说过「时间你不用管了」），也不把「去群里确认截止」写进任何文件。排期自己定好告知即可，不要把「今晚读哪份」甩回给用户。

### 2. 动笔前的核对（Claude 自己做，结果写进任务书）
- **作业**：题单常是同学打字整理的——会漏条件、缩题、加错 Hint，更正只发在群里。逐题定位到老师原文页码，列出「打字版 vs 原文」差异；比文件存入时间和群更正时间判断是不是旧版。
- **验算基线**：计算题用 sympy + 数值验算；反演类题把答案做正变换代回题面最快。老师的例题也会错（某讲义 §1.4 五题错三题），引用前一律代回验证。
- **定理条件以渲染页为准**：文字层会丢闭包横线、上标，凡要裁定「讲义有错」都先渲染那一页看。

### 3. 选产出类型
按用户当前所处阶段选，格式细节见 `references/formats.md`：

| 场景 | 产出 |
|---|---|
| 作业到了 | 作业讲解（每题五段式） |
| 新讲义到了，用户以视频/教材为主线 | 对照导航卡（老师编号↔视频↔教材、老师独有内容、笔误） |
| 考前 | 零基础补课册（K 条目）+ 题型解法卡（T 条目，原型题完整解） |
| 编程类上机/代码作业 | 带做卡（每题六步：翻译→问什么→小步手算→名字来源表→代码→找错） |
| 物理章节 | 以题为主的章节包（方程凭什么列、ODE 真解一遍、图截图嵌入） |

写法总纲（读者画像、轻量化、零基础、语言分科、禁用词）见 `references/writing.md`。**写任务书前读一遍**，因为用户的写法偏好变过好几次，最新的优先。

### 4. 写任务书
用 `references/task-book.md` 的模板。要点：
- 任务书**自包含**：Codex 读不到 Claude 的记忆，只读仓库文件和任务书。
- **凡是必须出现的内容，一律写进末尾「阻断项」清单**，不要埋在正文段落——较弱档位会丢掉段落里的「顺带」指令。
- 「详细解题」类任务要么附一道 Claude 亲手写的**完整黄金范例**，要么明令「每题 ≥N 步编号推导、禁止通用套话」；只给压缩基线会被做成空模板。
- **永远不要把给 agent 的话写进 Codex 会读进成品的源料文件**，会被原样印进 PDF。
- 指路页码要求「用脚本在 PDF 里查实」，不许估。
- 要求边做边写 `progress.md`，额度中断能续跑。

### 5. 派发
默认用 `dispatch` 在常年在线的那台机器后台跑（长任务一律不放在会合盖的笔记本上）。档位：讲义/导航/题型类 **Sol + high**；纯上机卡可用 Terra 但阻断项要写全；**不用 Luna**（长上下文召回差，本流程每次都是多文档综合）；卡住时单张升 `max`，**不开 ultra**（并行子 agent 会各自重讲共享背景）。

### 6. 验收
见 `references/acceptance.md`。核心：
- **阻塞（退回）**：数学错、漏讲原文条目/漏题、公式没渲染、图没嵌、越界讲老师没讲的、违反当前写法要求（如该中文却写了英文证明）。
- **不阻塞**：孤悬标题、行距、页数、表格宽度——顺手改或记进日志，不单开返工轮（用户：「能看得过去就进行下一项」）。
- **能程序化的必须跑脚本**，肉眼看几十页不漏是幻觉：
  ```bash
  python3 scripts/check_all.py 成品1.pdf 成品2.pdf --md 源码.md
  ```
  每条报出来的仍要渲染原页确认；返工件要**全量重扫**（修复动作会引入新缺陷）。
- Codex 写「已完成/已验证」的表格会打假勾，凡打勾的都回查正文；它报的「⚠️ 讲义存疑」也要渲染原页复核，错的存疑会让用户错怪老师。
- 篇幅不是质量的函数：薄不薄只能逐条读。

### 7. 落位与记录
- 成品 PDF → 用户每天打开的成品目录（如 `2_每周学习包/<课程>/`），**那里不放 .md**；源码 md → 系统目录 `源码md/<课程>/`。成品按序号/周次命名，不加日期。
- **重编已交付的成品前先查 `page.annots()`**：用户会直接在 PDF 上高亮批注，覆盖就抹掉了。有批注就另存 `_v2` 或先问。
- 每步追加日志（`cat >>`，只追加不回改）；更新**人话版进度总览**（任务编号对用户是黑话，要写「这是什么、做到哪、文件在哪、为什么急」）；更新该课的「先读我」索引。
- 两台机器都会写同一个日志时，iCloud 断连恢复后查冲突版本。

## 三、对话里直接带做（不出卡时）

用户在 notebook 里边做边问时，Claude 可以直接带（这不是生成成品）。用户编程零基础，节奏要慢：
- **一条消息只推进一小步**，让他做完/答完再往下；别一次铺开全部题目，别塞自测题和多套图示。
- 每题照带做卡的六步走（见 `references/formats.md` §4），先口头给式子再让他敲。
- 桌面 App 里 `$$` 带 `\\` 的矩阵、含 `\|` 的公式会显示成源码：矩阵用代码块画方格，范数写 Unicode。
- 读他的进度：让他 Cmd+S 后直接读 `.ipynb` 文件，不要连进他的 kernel 执行代码。
- 不帮忙把作业改得「看不出是 AI 做的」——课程明文禁止，简短回绝后提供能做的帮助（带做、检查、讲找错）。

## 四、出片

`scripts/build_pdf.py`（pandoc + xelatex + ctexart + `assets/header.tex`）：

```bash
python3 scripts/build_pdf.py 源码.md -o 成品.pdf --head-left "泛函分析 · 考前复习" --head-right "0a 零基础补课"
```

字体、emoji、源图嵌入、iCloud 路径等坑见 `references/pdf-engineering.md`。
